# D03 用户下单与商家履约交互验收清单

> 任务：`[D03][B][2026-08-27] 补齐用户下单与商家履约页面的可测试交互`
> 范围：CR-03 用户下单/支付、CR-04 团购核销、CR-05 评价、CR-06 商家履约

## 完成结果

- 购物车数量、删除、清空和下单操作增加互斥提交状态，连续点击只触发一次请求。
- 订单支付、取消、确认收货和提交评价增加互斥提交状态与失败提示，失败后可重新操作。
- 支付失败重试复用同一订单的 `clientRequestId`，成功后才清除，配合后端幂等约束避免重复支付。
- 商家履约按钮按状态显示“接单”“开始配送”“完成订单”，补齐 `DELIVERING -> COMPLETED` 页面入口。
- 团购券码输入只保留数字并限制 12 位；格式不完整时禁用核销，接口失败保留原券码便于修正或重试。
- 关键动作提供稳定 `data-testid`，数量按钮和券码输入补充可访问名称。

## 可重复验收

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| D03-01 | 购物车选择地址后连续点击“创建待支付订单” | 只提交一次；按钮显示“订单创建中…”且其他购物车动作暂时禁用 |
| D03-02 | 待支付订单连续点击“支付” | 只触发一次支付；按钮显示“支付中…”；失败后恢复并显示服务端错误 |
| D03-03 | 待支付订单点击“取消” | 操作期间显示“取消中…”并阻止重复动作 |
| D03-04 | 配送中订单点击“确认收货” | 操作期间显示“确认中…”并阻止重复动作 |
| D03-05 | 完成订单填写合法评分和内容后提交评价 | 操作期间显示“提交中…”；成功后收起表单并刷新订单 |
| D03-06 | 商家依次处理已支付、已接单、配送中订单 | 分别显示“接单”“开始配送”“完成订单”，请求下一合法状态 |

| D03-08 | 核销接口返回无效、已使用或越权错误 | 页面展示原始业务错误并保留券码，允许修正后重试 |
