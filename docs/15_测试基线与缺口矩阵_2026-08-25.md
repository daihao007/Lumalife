## 5 CR-01~CR-06 测试缺口矩阵

状态定义：**已覆盖**表示已有自动化用例直接验证该层的关键行为；**部分覆盖**表示只覆盖子场景或权限边界；**缺口**表示当前没有对应自动化测试。缺口不等同于功能失败。

| 需求 | 关键业务场景 | 业务规则测试 | API 集成测试 | 浏览器 E2E | 现有证据与缺口 |
|---|---|---|---|---|---|
| CR-01 用户认证与个人中心 | 登录、注册、角色鉴权、地址管理 | 已覆盖 | 部分覆盖 | 缺口 | `normalUserLoginCanReturnNullMerchantId`、`registerCreatesNormalUserWithEncodedPassword`、`userCanOnlyKeepFiveAddresses`；接口覆盖登录、匿名和角色越权。仍缺注册/资料/地址的正向 API 链路和浏览器流程。 |
| CR-02 商家搜索、分类、推荐与详情 | 搜索、排序、筛选、详情 | 已覆盖 | 部分覆盖 | 缺口 | `merchantListSupportsSortAndFilters`；接口覆盖公开商家列表、筛选排序和部分详情读取。仍缺分类入口、推荐理由、详情页商品/评价的完整接口与浏览器流程。 |
| CR-03 购物车、下单、模拟支付、订单跟踪 | 加购、拆单、地址快照、支付、取消、状态展示 | 已覆盖 | 部分覆盖 | 缺口 | `cartItemQuantityCanBeChangedAndRemoved`、`cartCanCreateSeparateDeliveryOrdersByMerchant`、`paymentIsIdempotentForSameClientRequestId`、`deliveryOrderUsesSelectedAddressSnapshot` 等；接口仅明确覆盖匿名访问购物车被拒绝，缺少登录后的购物车—下单—支付—取消正向 API 链路。 |
| CR-04 团购购买、券码生成、商家核销 | 团购下单、支付、12 位券码、核销 | 部分覆盖 | 缺口 | 缺口 | `paymentDeductsGroupDealStockOnceForSameRequest` 覆盖团购支付幂等与库存。缺少券码格式/生成、非本店券、重复核销、核销成功的业务规则和 API/E2E 测试。 |
| CR-05 评价与评分统计 | 可评价条件、一单一评、评分更新 | 已覆盖 | 缺口 | 缺口 | `completedOrderRequiresReviewContent`、`merchantCanSeeReviewsForOwnOrders`、`merchantStatsAreAffectedByPaidOrdersAndReviews` 覆盖核心规则。缺少评价提交和商家查看评价的正向 API/E2E 测试。 |
| CR-06 商家后台 | 订单履约、商品维护、团购套餐维护、核销 | 部分覆盖 | 部分覆盖 | 缺口 | `illegalMerchantStateTransitionIsRejected`、`merchantCannotToggleOtherMerchantProduct`、`merchantCanDeleteOwnProductAndRemoveItFromCarts` 覆盖部分规则；接口覆盖商家权限、注册、资料和助手。缺少订单正向履约、商品/团购套餐 CRUD、券码核销的正向 API/E2E 测试。 |

## 6 缺口优先级与后续测试建议

| 优先级 | 缺口 | 建议测试场景 | 关联需求 |
|---|---|---|---|
| P1 | 用户消费闭环的正向 API 链路 | 登录 → 加购 → 选择地址 → 下单 → 支付 → 取消或确认收货；断言响应结构、库存和订单状态。 | CR-03 |
| P1 | 团购券完整性与核销边界 | 支付生成 12 位券码、所属商家核销成功、非所属商家拒绝、重复核销拒绝。 | CR-04、CR-06 |
| P1 | 商家履约与后台维护 API | 商家接单/配送/完成、商品和团购套餐新增编辑上下架删除。 | CR-06 |
| P2 | 评价 API 正向链路 | 已完成订单可评价、重复评价被拒绝、商家评分更新且商家仅能读取本店评价。 | CR-05 |
| P2 | 认证和商家发现 API 补齐 | 注册、个人资料和地址 CRUD；分类、详情商品/团购/评价和推荐理由。 | CR-01、CR-02 |
| P2 | 多角色浏览器 E2E | 用户消费闭环、商家履约/核销、管理员看板三条主流程。可优先引入 Playwright。 | CR-01~CR-06 |
