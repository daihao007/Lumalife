## 1. 本次验收结论

- 前端页面已从不可追踪的组件内 `view` 状态补齐为稳定 Hash 路由，刷新和复制链接后仍能定位到同一页面。
- 登录后按角色进入固定工作台：普通用户 `#/discover`、商家管理员 `#/merchant/orders`、平台管理员 `#/admin`。
- 前端路由守卫对游客和角色越权给出明确提示并跳转安全页面；后端仍以 Spring Security 的 401/403 作为最终权限边界。
- 商家详情使用 `#/merchants/{id}`，支持刷新后按商家 ID 恢复页面，不依赖上一次组件内状态。
- 已增加 11 项自动化测试：6 项纯路由策略测试和 5 项 App 组件接线测试，覆盖路径解析、根地址规范化、详情深链与乱序响应、角色隔离、游客保护、无效 Token 和默认工作台；`npm test`、`npm run build` 均通过。

## 3. 角色访问矩阵

| 路由类别 | 游客 | USER | MERCHANT_ADMIN | PLATFORM_ADMIN |
| --- | --- | --- | --- | --- |
| 发现、商家详情、公共客服 | 允许 | 允许 | 拒绝 | 拒绝 |
| 登录/注册 | 允许 | 返回用户首页 | 返回商家工作台 | 返回平台看板 |
| 购物车、订单、收藏、资料 | 跳转登录 | 允许 | 拒绝并返回商家工作台 | 拒绝并返回平台看板 |
| 商家订单、商品、客服、店铺 | 跳转登录 | 拒绝并返回用户首页 | 允许 | 拒绝并返回平台看板 |
| 平台看板 | 跳转登录 | 拒绝并返回用户首页 | 拒绝并返回商家工作台 | 允许 |
| 不存在的地址 | 返回发现页并提示 | 返回用户首页并提示 | 返回商家工作台并提示 | 返回平台看板并提示 |

前端提示分为三类：游客显示“请先登录后再访问该页面”；已登录但角色不符显示“当前角色无权访问该页面，已返回工作台”；未知地址显示“页面地址无效，已返回工作台”。

## 4. CR-01～CR-06 路由追溯

| 需求 | 入口链路 | 角色/权限检查 | 可验证结果 |
| --- | --- | --- | --- |
| CR-01 认证与个人中心 | `#/login → #/discover 或角色工作台`；用户 `#/profile` | 无 Token 访问用户页跳登录；登录后按 USER/MERCHANT_ADMIN/PLATFORM_ADMIN 分流 | 登录、刷新恢复身份、资料页入口和角色隔离可复现 |
| CR-02 发现与详情 | `#/discover → #/merchants/{id} → #/favorites` | 发现和详情公开；收藏仅 USER | 商家详情链接可复制、刷新恢复；游客收藏跳登录 |
| CR-03 购物车与订单 | `#/merchants/{id} → #/cart → #/orders` | 三个交易入口中购物车/订单仅 USER | 游客不能进入结算，商家/平台角色不能进入用户交易页 |

| CR-05 评价 | 用户 `#/orders`；商家 `#/merchant/orders`；公开详情 `#/merchants/{id}` | 提交评价仅认证用户；商家仅查看本店订单/评价 | 用户评价、商家查看、详情展示三段链路可定位 |
| CR-06 商家后台 | `#/merchant/orders/products/shop`；平台 `#/admin` | 商家路由只允许 MERCHANT_ADMIN；平台看板只允许 PLATFORM_ADMIN | 商家经营入口与平台观测入口互不混用 |

## 6. 后端权限复核

前端路由守卫只负责入口和用户提示，不能代替服务端鉴权。`SecurityConfig` 当前规则为：

- `/api/v1/auth/**`、商家目录、分类等公开接口允许匿名访问；
- `/api/v1/admin/**` 只允许 `PLATFORM_ADMIN`；
- `/api/v1/merchant-admin/**` 只允许 `MERCHANT_ADMIN`；
- 其余 `/api/v1/**` 要求已认证。

因此，即使绕过前端直接调用接口，匿名请求仍返回 401，角色越权仍返回 403。
