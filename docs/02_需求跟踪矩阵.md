# 需求跟踪矩阵

| 需求 ID | 后端模块 | 前端页面 | 测试用例 | 状态 |
|---|---|---|---|---|
| CR-01 | Auth、Security、Address、DemoStore | Login、侧边账号区、Profile | 登录成功/密码错误/角色路由/地址上限 | 部分实现/待补验证 |
| CR-02 | Merchant API | Home、Detail | 搜索、分类、推荐排序 | 部分实现/待补验证 |
| CR-03 | Cart、Order、Payment | Detail、Cart、Orders | 同商家限制、数量修改、删除/清空、待支付取消、支付幂等、状态时间线 | 部分实现/待补验证 |
| CR-04 | GroupOrder、Coupon | Detail、MerchantDesk | 券码生成、重复核销、越权核销 | 部分实现/待补验证 |
| CR-05 | Review | Orders、Detail | 未完成不可评、重复不可评、评分范围 | 部分实现/待补验证 |
| CR-06 | MerchantAdmin、Product、GroupDeal | MerchantDesk | 接单、配送、完成、核销、商品越权、上下架 | 部分实现/待补验证 |

状态口径：`部分实现/待补验证` 表示代码和 API 级测试已覆盖主要成功规则，但前端仍存在游客入口/页面错误态等体验缺口，且完整手工/E2E 证据尚未冻结；不等同于后端功能全部缺失。当前候选基线中的 `DELIVERING → COMPLETED` 入口和普通用户路径 `ROLE_USER` 限制已经落地，详见 [前端覆盖盘点](13_前端页面与用例覆盖盘点.md) 与 [测试基线](15_测试基线与缺口矩阵_2026-08-25.md)。
