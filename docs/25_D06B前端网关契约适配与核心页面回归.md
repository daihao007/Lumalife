# D06B 前端网关契约适配与核心页面回归

日期：2026-08-31  
冻结依据：`docs/16_三服务接口数据归属与契约草案.md` 第 2、4、10 节（外部 v1 兼容候选）。

## 适配结论

- 页面继续只调用同源网关 `/api/v1/**`，未暴露或调用 `/internal/**`、`8081`、`8082`、`8083`；服务拆分不改变前端业务路径。
- `frontend/src/api.ts` 统一注入 Bearer token 和 `X-Request-Id`，并支持部署环境通过 `VITE_GATEWAY_BASE_URL` 指定网关基址（默认同源）。
- 成功只接受冻结的 envelope（`code: 200`；异步 202 保留状态码同值兼容）；错误保留 `status/code/requestId/reason/details` 供页面恢复处理，非 JSON 的 502/503 不会造成 JSON 解析异常。
- 注册请求不再发送客户端 `role` 字段：普通与商家注册的身份由各自冻结端点决定，避免客户端角色提权。

## 回归范围

- API 契约：网关路径约束、鉴权与请求 ID、503 扩展错误外壳、非 JSON 502。
- 核心页面：现有 `App.routing.test.tsx`、`pages/CoreFlowIntegration.test.tsx`、`pages/OrderInteractions.test.tsx`、`pages/UC07PageFlow.test.tsx` 覆盖用户下单/支付、商家履约和平台页面恢复。
- 浏览器 E2E：`ui-e2e/tests/core-flows.spec.ts` 覆盖登录详情、地址下单和用户—商家客服往返；须在已启动的后端和前端环境执行。
