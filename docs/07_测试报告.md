## 1 引言

### 1.1 目标

本文档用于记录 LumaLife 综合生活助手平台的测试计划、测试范围、测试方法、测试用例、执行日志和测试总结，验证系统是否满足课程验收场景下的核心业务需求。

### 1.2 背景

LumaLife 是一个本地生活服务演示系统，包含普通用户端、商家管理端和平台管理端。系统覆盖商家发现、商品加购、地址管理、外卖下单、团购购买、模拟支付、订单履约、评价、客服会话、AI 辅助回复和平台看板等功能。

### 1.3 范围

本报告覆盖以下测试范围：

| 业务规则测试 | 库存扣减、幂等支付、订单状态流转、地址数量限制、团购核销 |

### 2.4 要测试的特征

1. 用户能通过不同角色账号登录并进入对应角色页面。
2. 未登录用户可浏览公开商家列表，但不能访问购物车和订单。
3. 普通用户可完成从浏览商家到支付、评价的消费闭环。
4. 商家管理员只能管理自己所属商家的订单、商品、团购和客服会话。
5. 平台管理员可查看账号和指标，但响应中不包含密码字段。
6. 支付请求使用 `clientRequestId` 保证同一请求重复支付不会重复扣减库存。
7. 订单状态必须按待支付、已支付、已接单、配送中、已完成等合法路径流转。
8. 客服会话和运营统计在状态文件恢复后仍可读取。
9. 前端生产构建可通过 TypeScript 检查和 Vite 打包。

## 3 测试设计说明

### 3.1 目的

测试设计用于将业务需求拆分为可执行的自动化用例和手工用例，保证消费闭环、履约闭环和平台观测闭环均被覆盖。

### 3.2 测试设计标识符

| 项目 | 内容 |
|---|---|
| 测试设计编号 | LumaLife-TD-20260611 |
| 设计对象 | 前端页面、后端接口、核心服务 |
| 设计方法 | 黑盒测试为主，结合核心服务白盒单元测试 |

### 3.3 方法细化

#### 3.3.1 用户侧

用户侧测试以“发现商家 -> 加购 -> 地址 -> 下单 -> 支付 -> 收货 -> 评价 -> 客服”为主线，重点验证跨商家拆单、库存扣减和状态时间线。

#### 3.3.2 商家侧

商家侧测试以“接收订单 -> 接单 -> 配送 -> 完成 -> 查看评价 -> 回复客服”为主线，重点验证商家只能操作自身资源。

#### 3.3.3 管理侧

管理侧测试以指标和账号安全为主线，重点验证平台管理员能看到必要统计，但不能看到密码字段。

#### 3.3.4 异常规则

异常规则覆盖无地址下单、非法状态流转、重复注册、越权访问、重复支付、空评价内容等场景。

### 3.4 特征通过准则

| 特征 | 通过准则 |
|---|---|
| 登录注册 | 正确账号能登录，重复账号注册被拒绝 |
| 权限控制 | 未授权访问返回 401，角色越权返回 403 |
| 购物车 | 数量更新、删除、清空结果正确 |
| 订单 | 状态流转合法，非法跳转被拒绝 |
| 支付 | 同一 `clientRequestId` 重复提交结果幂等 |
| 库存 | 支付后库存按购买数量扣减且不重复扣减 |
| 看板 | 指标和账号列表可展示，响应不含密码 |
| 构建 | 前端构建成功，后端测试通过或失败项有明确记录 |
