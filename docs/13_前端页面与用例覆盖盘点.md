# D01 前端页面与用例覆盖盘点

> 任务：[#17](https://github.com/daihao007/Lumalife/issues/17)  
> 日期：2026-08-25  
> 负责人：Chrmysle  
> 范围：CR-01～CR-06；用户、商家、平台管理员三个现有角色

## 1. 结论

- 当前正式导航包含 **13 个页面组件**：公共/用户端 8 个、商家端 4 个、平台管理员端 1 个。
- CR-01～CR-05 均已有可访问页面和主要成功路径；CR-06 的商家履约页面缺少“配送中 → 完成”操作，是中期演示前必须修复的 P0 缺口。
- 角色导航由 `frontend/src/App.tsx` 中的 `user.role + view` 控制；后端仅对 `/api/v1/admin/**` 和 `/api/v1/merchant-admin/**` 做角色校验，其余 `/api/v1/**` 仅要求已登录。因此商家和平台管理员仍可调用购物车、地址、订单等普通用户接口，属于 P1 权限矩阵缺口。
- 当前没有前端自动化测试命令，也没有稳定 URL 路由；后续 E2E 只能依赖按钮文本和页面状态，需在 D02～D04 补齐稳定选择器、错误态和自动化测试。
- `MerchantDesk.tsx` 是旧聚合页，保留了重复实现但没有正式菜单入口；当前商家端以 Orders、Products、Support、Shop 四个拆分页面为准。

## 3. CR-01～CR-06 前端覆盖矩阵

| 需求 | 页面链路 | 主成功流程 | 备选/异常流程 | 覆盖结论 |
|---|---|---|---|---|
| CR-01 用户认证与个人中心 | Login → Home/Profile；角色登录后进入各自工作区 | 用户/商家登录注册；平台管理员登录；资料与地址维护 | 密码错误、重复账号、地址上限、角色跳转、401/403 | **部分覆盖**；需补游客受保护入口提示、登出后本地数据清理、页面级错误态，以及商家/平台管理员访问普通用户接口的 403 回归测试 |
| CR-02 商家发现与详情 | Home → Detail → Favorites | 分类/关键词/价格/评分筛选与排序；查看商品、团购、评价；收藏 | 非法价格区间；空结果；接口失败 | **主要流程覆盖**；空结果和加载失败提示不足 |
| CR-03 购物车、下单、支付与跟踪 | Detail → Cart → Orders → StatusTimeline | 已登录用户可加购、分商家展示、改数量、清空、选地址、下单、支付、订单时间线、确认收货 | 无地址、待支付取消、已支付不可取消、支付失败、重复点击、游客操作 | **部分覆盖**；支付缺少提交中和稳定幂等请求标识；游客加购/结算无登录提示；登出后购物车/地址本地状态未清空 |
| CR-04 团购购买与核销 | Detail → Orders → MerchantOrders | 已登录用户可团购购买并支付、显示 12 位券码、商家核销 | 重复核销、无效券码、其他商家越权核销、游客购买 | **部分覆盖**；游客仍可见购买按钮但无登录提示；核销失败缺少可理解的页面提示 |
| CR-05 评价与评分 | Orders → Detail / MerchantOrders | 完成订单后填写三项评分和内容；用户/商家查看评价 | 未完成不可评、空内容、非法评分、重复评价 | **主要流程覆盖**；前端已做内容和 1～5 分校验，重复评价依赖后端结果 |
| CR-06 商家后台 | MerchantOrders / Products / Shop | 接单、进入配送；商品与团购维护；店铺资料；核销券码 | 非法状态流转、跨商家越权、非法价格/库存、删除确认 | **部分覆盖**；缺少“配送中 → 完成”入口；后端未阻止商家/平台管理员调用普通用户接口，必须补齐 USER 角色边界与回归测试 |

## 4. 角色与权限入口

| 身份 | 可见导航 | 登录后的默认页面 | 后端实际权限与验收结论 |
|---|---|---|---|
| 游客 | 发现、购物车、客服、登录 | Home | 公开接口可访问；受保护接口返回 401，但购物车、详情页购买入口未跳转登录。 |
| USER | 发现、购物车、订单、收藏、地址、客服、退出 | Home | 商家后台和平台看板接口均返回 403。 |
| MERCHANT_ADMIN | 订单、商品、客服、店铺、退出 | MerchantOrders | 商家后台可访问、平台看板返回 403；但 `/api/v1/cart/**`、`/api/v1/user/**`、`/api/v1/orders/**` 等普通用户接口当前只要求已登录，未保证 403。 |
| PLATFORM_ADMIN | 看板、退出 | Admin | 平台看板可访问；普通用户接口同样只要求已登录，未保证 403。 |

说明：前端入口控制仅改善体验，不能替代后端鉴权。`SecurityConfig` 目前仅对平台和商家后台路径使用 `hasRole`；应补齐 USER 专属路径的角色校验，并覆盖游客、用户、商家和平台管理员的越权结果。

## 5. 可重复演示路径

### 路径 A：用户消费闭环（CR-01、CR-02、CR-03、CR-05）

1. 使用普通用户账号登录。
2. 在发现页按关键词/分类搜索并进入商家详情。
3. 加购商品，进入购物车修改数量并选择地址。
4. 创建订单、模拟支付，在订单页查看状态时间线。
5. 当前可执行步骤是商家将订单推进到 `DELIVERING`，随后用户确认收货进入 `RECEIVED` 并提交评价；商家侧 `DELIVERING → COMPLETED` 需修复后才可演示。
6. 返回商家详情确认评价可见、评分统计发生变化。

### 路径 B：团购闭环（CR-04）

1. 用户在商家详情购买团购套餐并自动支付。
2. 用户订单页展示 12 位券码。
3. 商家登录，在订单页输入券码并核销。
4. 再次核销同一券码，验证系统返回确定错误且不重复改变状态。

### 路径 C：商家经营路径（CR-06）

1. 商家登录后进入订单页，当前只能执行 `PAID → ACCEPTED → DELIVERING`。
2. 在商品页新增/编辑商品和团购，验证上下架和库存输入校验。
3. 在店铺页修改商家名称，返回用户发现页核对名称同步。
4. 在订单页核销券码并查看用户评价。

> 修复 `DELIVERING → COMPLETED` 按钮后，才可将本路径称为完整商家履约闭环；当前不把该步骤作为可重复演示的既有能力。

### 路径 D：平台观测与权限

1. 平台管理员登录后自动进入看板。
2. 展示用户/商家/订单/营收指标、订单图表、商家排行、健康和日志。
3. 用普通用户或商家身份请求平台接口，验证返回 403。

## 6. 缺口与修复优先级

| 优先级 | 缺口 | 影响 | 建议落入任务 |
|---|---|---|---|
| P0 | `MerchantOrders.tsx` 只支持 PAID → ACCEPTED → DELIVERING，缺少 DELIVERING → COMPLETED | 阻塞 CR-06 的完整商家履约链路和中期演示；不严格阻塞 CR-05，用户仍可在 DELIVERING 状态确认收货进入 RECEIVED 后评价 | D02/D03 前端交互任务，后端共同复核状态机 |
| P1 | 前端没有测试脚本和 E2E 框架 | 课程要求全部用例端到端自动化，当前只能手工回归 | D03 建框架，D04 完成 CR-01～CR-06 E2E |
| P1 | 页面使用本地 `view` 状态，没有 URL 路由或稳定深链 | 刷新/直达页面困难，E2E 定位和失败复现不稳定 | D02 页面与路由验收清单 |
| P1 | 支付、下单、核销、状态流转缺少统一提交中/防重复点击 | 容易重复请求；支付每次点击都会生成新的 `clientRequestId` | D03 可测试交互与异常提示 |
| P1 | 核销、商品加载、会话加载等请求存在静默 `catch` 或未捕获 Promise | 失败时用户看不到可理解原因，无法演示异常流程 | D03/D04 联调和 E2E |
| P1 | 普通用户 API 仅要求认证，未限制 `USER` 角色 | 商家或平台管理员可调用购物车、地址、订单等用户接口，前端隐藏导航不能构成安全边界 | D02 补 `hasRole(USER)` 或控制器角色校验；D03 增加商家/平台管理员访问用户接口的 403 回归测试 |
| P1 | 登出未清空 `cart`、`addresses` 和已选地址 | 游客或下一位登录者可能看到上一位用户的本地购物车与地址，属于隐私风险 | D02 清理会话状态；D03/D04 增加登出—游客—重新登录的回归与 E2E |
| P1 | 游客在详情页仍可见加购、购买团购按钮 | 请求会因未认证失败但无提示/跳转登录，CR-01、CR-03、CR-04 演示失败 | D02 按登录态隐藏或拦截操作并跳转登录；D03 添加游客操作回归测试 |
| P1 | 游客可进入购物车，但只看到空购物车，没有登录提示或 401 展示 | CR-01 权限演示不清晰；与登出残留风险叠加 | D02 角色路由验收 |
| P2 | Admin 初始化加载态只有英文，接口失败态缺失；排行榜、活跃订单和日志已有空态 | 平台看板弱网或接口失败时不易定位 | D04 核心流程联调 |
| P2 | `MerchantDesk.tsx` 与四个新商家页面重复且无菜单入口 | 增加维护和测试歧义 | 中期前确认删除或明确标记为 legacy |
| P2 | 多数关键按钮缺少稳定 `data-testid` 或统一可访问名称 | E2E 容易受文字和布局调整影响 | D02/D03 前端可测试性改造 |
