# 详细设计说明

## 后端类设计

- `ApiResponse`：统一响应格式。
- `BusinessException`：业务异常，映射到统一错误响应。
- `SecurityConfig`：Token 过滤器和角色访问控制。
- `AuthService`：认证、当前用户、个人资料和地址管理门面。
- `CatalogService`：分类、商家搜索和商家详情门面。
- `CartService`：购物车查询、加购、修改、删除和清空门面。
- `OrderWorkflowService`：外卖下单、团购下单、支付、取消、用户订单和评价门面。
- `MerchantAdminService`：商家订单履约、商品维护、团购维护、券码核销和商家评价门面。
- `AdminDashboardService`：平台管理员指标看板门面。
- `AssistantService`：规则型 AI 客服门面。
- `DemoStore`：当前演示版内存数据与核心业务实现，集中维护用户、商家、商品、购物车、订单、券码、评价和日志；后续数据库迁移时可逐步替换为 Mapper/Repository。
- `ApiControllers`：REST API 入口，只做参数接收和 Service 调用。

## 事务边界设计

演示版使用同步内存方法保证原子更新。迁移数据库时，以下方法应加 `@Transactional`：

- 创建订单和写入订单明细。
- 支付成功、写入支付记录、更新订单状态。
- 团购支付后生成券码。
- 评价提交后更新商家评分。
- 商家订单状态流转。
- 券码核销。

## 状态与权限

- 状态字段统一使用枚举，不使用散落字符串。
- 商家处理订单时校验 `order.merchantId == currentUser.merchantId`。
- 普通用户查询订单时校验 `order.userId == currentUser.id`。
- 未登录访问受保护接口返回 401。
- 已登录但角色不匹配访问受保护接口返回 403。
