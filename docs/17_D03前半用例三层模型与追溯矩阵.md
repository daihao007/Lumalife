## 1. 验收口径

本交付将旧版核心范围编号与正式编号统一对齐：`CR-01 → REQ01 → UC01`、`CR-02 → REQ02 → UC02`、`CR-03 → REQ03 → UC03`。三层模型的边界如下：

1. **系统级（SYS）**：参与者与 LumaLife 业务能力之间的目标关系，回答“系统为谁完成什么目标”。
2. **组件级（COMP）**：前端页面、`api.ts`、`ApiControllers`、安全组件、业务 Service 和 `DemoStore` 之间的调用关系，回答“哪个可部署/可维护组件协作完成目标”。
3. **对象级（OBJ）**：`Models.java` 中的领域对象、Service 方法和存储集合之间的协作与状态变化，回答“哪些对象实际完成规则”。

图中的页面、接口、服务、领域对象和测试方法均以仓库当前实现为准；`DemoStore` 是当前单体演示版的实际状态边界，不将未来数据库或微服务写成当前实现。

## 6. 验收结论与限制

- `CR-01`～`CR-03` 均已分别提供 `SYS`、`COMP`、`OBJ` 三层图源，并提供由对应 Mermaid 源文件直接生成的 9 个 SVG 导出图。
- 每个核心范围均可从图标识追到 `REQ/UC`、代码入口、接口路径和 `TC-UCxx-nn` 测试编号。
- 本交付补齐的是模型和追溯证据，不宣称新增浏览器 E2E；手工用例只按测试报告中实际执行的步骤描述，未覆盖的取消/时间线由自动化测试证据承载。
- 当前实现是单体 Spring Boot + React/Vite + `DemoStore`；图中没有把预留的 MySQL、Redis 或未来服务拆分误标为当前调用链。

## 7. SVG 导出复现

每张 SVG 都由同名 `.mmd` 源文件直接生成，使用 Mermaid CLI 复现：

```bash
for name in CR-01-SYS-CR01 CR-01-COMP-CR01 CR-01-OBJ-CR01 \
  CR-02-SYS-CR02 CR-02-COMP-CR02 CR-02-OBJ-CR02 \
  CR-03-SYS-CR03 CR-03-COMP-CR03 CR-03-OBJ-CR03; do
  npx --yes @mermaid-js/mermaid-cli@11.12.0 \
    -i "docs/diagrams/d03/$name.mmd" \
    -o "docs/assets/d03/$name.svg" --quiet
done
```

导出校验：9 个 Mermaid 图块渲染通过，9 个 SVG 文件非空且通过 `xmllint --noout`。
