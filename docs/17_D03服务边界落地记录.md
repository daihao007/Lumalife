# D03 服务边界落地记录

> 对应 Issue：[#28](https://github.com/daihao007/Lumalife/issues/28)<br>
> 目标：在单体基线上整理用户认证、商家商品与订单接口的服务边界，保持 `/api/v1` 前端兼容。

## 1. 落地范围

本次采用单体内模块化，不进行数据库、进程或网络层面的物理拆分。Controller 仍是兼容适配层，业务能力通过领域端口隔离：

| 目标服务 | 单体入口 | 负责能力 | 不负责 |
|---|---|---|---|
| identity-service | `IdentityServicePort` → `AuthService` | 登录、注册、当前用户、资料、收货地址、令牌验证 | 商家资料、商品、购物车、订单 |
| merchant-service | `MerchantServicePort` → `CatalogService` / `MerchantAdminService` / `FavoriteService` / `AssistantService` | 分类、商家、商品、团购套餐、收藏、商家客服 | 订单状态、支付、评价事实 |
| order-service | `OrderServicePort` → `CartService` / `OrderWorkflowService` / `OrderAdminService` | 购物车、下单、支付、取消、收货、订单列表、评价、商家履约与券码 | 用户账户、商品主数据 |
| platform read model | `MetricsServicePort` → `AdminDashboardService` | 运营指标查询 | 其他服务源数据写入 |

端口中的 `userId`、`merchantId`、`productId` 和 `orderId` 是跨边界引用；后续物理拆分时替换端口适配器即可，不能将 `DemoStore` 或共享 Entity 包复制到多个服务。

## 2. 接口归属

- identity：`/auth/**`、`/user/profile`、`/user/addresses/**`。
- merchant：`/categories`、`/merchants/**`、`/user/favorites/**`、`/conversations/**`、`/merchant-admin/profile`、`/merchant-admin/products/**`、`/merchant-admin/group-deals/**`、商家客服接口。
- order：`/cart/**`、`/orders/**`、`/payments`、`/reviews`、`/merchant-admin/orders/**`、`/merchant-admin/reviews`、`/merchant-admin/coupons/verify`、`/admin/metrics`。

商家后台的商品写入和订单履约已经由两个不同门面承载：`MerchantAdminService` 不再暴露订单方法，订单命令统一经过 `OrderAdminService`。商家名称变更不再回写历史订单的 `merchantName` 快照；新订单读取当前商家名称。

## 3. 鉴权和错误契约

- URL 角色规则保持不变：普通用户、商家管理员、平台管理员分别限制到对应路径；TokenFilter 只依赖 `IdentityServicePort`。
- 普通 `/auth/register` 忽略角色提升路径：请求显式提交 `MERCHANT_ADMIN` 返回 `40000 / ROLE_NOT_ALLOWED`；商家注册继续使用显式的 `/auth/register/merchant` 兼容入口。
- 401、403 不再返回空响应；与业务异常统一返回 `code/message/data/requestId/reason/details` 错误外壳。
- 服务端异常对外只返回安全文案“服务暂时不可用”，不泄漏堆栈、SQL 或原始异常信息；`X-Request-Id` 会回传并写入响应。

业务码仍保持 v1 兼容：`40000` 参数、`40100` 未认证、`40300` 越权、`40400` 不存在、`40900` 状态/库存/幂等冲突。

## 4. 可运行证据

契约样例位于 `backend/src/test/java/com/lumalife/controller/ServiceBoundaryContractTest.java`，覆盖匿名 `/auth/me` 和普通注册角色越权，并断言 HTTP 状态、统一错误码、稳定 reason 与 requestId。
