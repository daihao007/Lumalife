# LumaLife 用户手册

> 状态：当前微服务验收版。本文按默认 `prod,remote` 运行模式描述操作；启动、服务和数据口径以根 README 与 [`project-facts.md`](project-facts.md) 为准。

## 1 引言

### 1.1 编写目的

本文档用于说明 LumaLife 综合生活助手平台的主要使用方法，帮助普通用户、商家管理员和平台管理员完成登录、浏览、下单、履约、客服、店铺维护和平台监控等操作。

### 1.2 项目背景

LumaLife 是一个面向课程验收场景的本地生活服务演示系统，覆盖用户消费闭环、商家履约闭环和平台观测闭环。系统采用 React + TypeScript + Vite 前端，由 backend BFF 统一提供公共 API，并调用 identity、merchant、order、assistant 四个业务微服务。默认 Compose 使用 MySQL 中的三个服务数据库保存身份、商家和订单数据，库存协作链路使用 RabbitMQ Outbox/Inbox/Saga。

### 1.3 适用对象

本文档适用于以下用户：

| 用户类型 | 主要职责 |
|---|---|
| 普通用户 | 浏览商家、收藏店铺、管理地址、加购商品、创建订单、模拟支付、评价订单、联系客服 |
| 商家管理员 | 处理订单、核销团购券、维护商品和团购套餐、回复客服消息、维护店铺名称 |
| 平台管理员 | 查看平台指标、账号列表、商家排行、活跃订单、系统健康状态和操作日志 |

### 1.4 访问地址

本地开发环境默认访问地址如下：

| 服务 | 地址 |
|---|---|
| 前端页面 | `http://localhost:5173/` |
| 后端接口 | `http://localhost:8080` |
| 健康检查 | `http://localhost:8080/actuator/health` |
| Swagger UI | `http://localhost:8080/swagger-ui/index.html` |

以上是面向使用者的外部入口。`8081`～`8084` 分别属于 identity、merchant、order、assistant 内部服务端口，普通用户不应绕过 backend BFF 直接访问。

### 1.5 使用前准备

推荐在仓库根目录启动默认八服务环境：

```bash

```

## 2 登录与注册

### 2.1 登录系统

1. 打开 `http://localhost:5173/`。
2. 点击左侧导航底部的“登录”按钮。
3. 输入手机号（登录名）和密码。
4. 点击登录后，系统会根据账号角色自动进入对应页面：
   - 普通用户进入发现页。
   - 商家管理员进入商家订单页。
   - 平台管理员进入平台看板页。

### 2.2 注册普通用户

1. 进入登录页面后切换到注册模式。
2. 选择普通用户角色。
3. 输入手机号、昵称、至少 6 位密码和确认密码；页面会显示密码强度，并支持显示或隐藏密码。
4. 提交后系统自动登录，并进入地址/个人资料相关页面。

![账号注册页面](assets/user-manual/01-register.png)

图 2-1 账号注册页面

### 2.3 注册商家账号

1. 进入注册模式。
2. 选择商家管理员角色。
3. 输入手机号、商家昵称（初始店铺名称）、至少 6 位密码和确认密码。
4. 提交成功后系统创建商家管理员账号和对应商家店铺，并进入商家后台。

### 2.4 退出登录

在左侧导航底部账号区域点击“退出”，系统会清除本地登录令牌并返回普通浏览状态。

## 3 普通用户操作说明

### 3.1 浏览和搜索商家

1. 登录普通用户账号，或以未登录状态进入首页。
2. 在“发现”页查看商家列表。
3. 可通过以下方式筛选商家：
   - 输入关键词搜索商家或商品。
   - 点击分类筛选，如川湘菜、咖啡茶饮、轻食简餐、甜品烘焙、生活服务。
   - 选择推荐，或按价格、评分、销量、距离升序或降序排序。
   - 设置人均价格区间和最低评分。
4. 点击商家卡片进入商家详情。

![发现页商家列表](assets/user-manual/02-discover.png)

图 3-1 发现页支持搜索、筛选、排序和收藏商家

### 3.2 收藏商家

1. 登录普通用户账号。
2. 在发现页点击商家卡片上的收藏按钮。
3. 在左侧导航进入“收藏”页面，可查看已收藏商家。
4. 再次点击收藏按钮可取消收藏。

### 3.3 查看商家详情

商家详情页展示以下信息：

| 区域 | 内容 |
|---|---|
| 店铺信息 | 店名、地址和推荐理由 |
| 商品列表 | 商品名称、描述、价格和加购按钮 |
| 团购套餐 | 套餐名称、描述、价格和购买按钮 |
| 用户评价 | 评分、用户昵称和评价内容 |
| 客服入口 | 可进入与当前商家的客服会话 |

![商家详情页](assets/user-manual/03-merchant-detail.png)

图 3-2 商家详情页展示菜单、团购和店家客服入口

### 3.4 加入购物车

1. 在商家详情页选择需要购买的商品。
2. 点击“加购”。
3. 系统会将商品加入当前用户购物车。
4. 点击“去购物车结算”或左侧“购物车”进入购物车页面查看明细。

### 3.5 管理收货地址

1. 进入左侧导航的“地址”页面。
2. 填写联系人、手机号、详细地址。
3. 点击保存后地址进入地址列表。
4. 可修改地址、取消修改、设置默认地址，也可删除不再使用的地址。
5. 同一页面可修改昵称并上传头像；头像必须是图片、不得超过 2 MB，浏览器会将长边压缩到不超过 512 像素后保存。
6. 当前系统限制每个普通用户最多维护 5 个收货地址。

### 3.6 创建外卖订单

1. 进入购物车页面。
2. 检查商品数量和小计。
3. 如需调整数量，可在购物车中修改数量；数量为 0 或点击删除时商品会被移除。
4. 也可使用“清空购物车”移除全部购物车项。
5. 选择收货地址；下单时会记录当前地址快照。
6. 点击创建订单。
7. 如果购物车中包含多个商家的商品，系统会按商家拆分生成多个待支付订单。

![购物车结算页面](assets/user-manual/04-cart.png)

图 3-3 购物车页面可调整数量、选择收货地址并创建待支付订单

### 3.7 模拟支付和取消订单

1. 进入“订单”页面。
2. 对待支付订单点击支付，系统执行模拟支付并将订单状态变为已支付。
3. 对待支付订单可点击取消。
4. 已支付订单不能由用户直接取消，需要进入商家履约流程。

![用户订单页面](assets/user-manual/05-orders.png)

图 3-4 订单页面展示订单状态、金额和状态时间线

### 3.8 确认收货和评价

1. 商家开始配送后，用户可在订单页面查看状态时间线，并点击“确认收货”。商家已标记完成的订单也允许用户确认。
2. 点击“查看详情”可查看商家、配送地址快照、商品单价和小计。
3. 对 `RECEIVED`、`COMPLETED` 或已核销 `USED` 且未评价的订单填写评价。
4. 综合、口味、服务三项评分都必须是 1～5 的整数，评价内容不能为空。
5. 提交后评价会进入商家评价列表，并影响商家评分统计。

### 3.9 购买团购券

1. 在商家详情页选择团购套餐。
2. 点击购买团购。
3. 系统创建团购订单并进行模拟支付。
4. 支付成功后生成团购券码。
5. 用户可将券码提供给商家管理员核销。
6. 如果订单已创建但支付结果未确认，应重试原订单支付，不要重复创建团购订单。

### 3.10 使用客服

普通用户支持两种客服入口：

| 入口 | 用途 |
|---|---|
| 访客左侧导航“客服” | 向平台 AI 助手提问 |
| 普通用户左侧导航“客服” | 查看已经建立的店家客服会话 |
| 商家详情页“联系商家” | 进入与当前商家的会话 |

普通用户首次联系客服时，应先从商家详情页选择商家。用户发送消息后，系统会记录会话，并可能先显示 AI 自动生成的店家回复；商家管理员仍可在商家后台查看并人工回复。

![店家客服会话页面](assets/user-manual/06-customer-service.png)

图 3-5 店家客服页面展示用户与商家的历史会话和输入框

## 4 商家管理员操作说明

### 4.1 进入商家后台

商家管理员登录后默认进入商家订单页面。左侧导航包含订单、商品、客服、店铺等入口。

### 4.2 处理订单

1. 进入“订单”页面。
2. 查看本商家的外卖订单和团购订单。
3. 对已支付外卖订单依次执行：
   - 接单。
   - 配送。
   - 完成。
4. 系统会记录订单状态时间线，用户可在订单页面查看。

### 4.3 核销团购券

1. 进入商家订单页面。
2. 在团购券核销区域输入用户提供的券码。
3. 券码必须是 12 位数字；不足 12 位或包含其他字符时不能提交。
4. 点击核销。
5. 系统校验券码是否存在、是否属于当前商家、是否已核销。

### 4.4 维护商品

1. 进入“商品”页面。
2. 填写商品名称、描述、价格和库存；新增商品默认上架。
3. 点击保存新增或更新商品。
4. 可通过列表中的按钮对已有商品执行上架或下架。
5. 可删除本商家商品；历史订单快照仍会保留。当前微服务模式不承诺自动清理 order-service 中已经存在的购物车项。

![商家商品维护页面](assets/user-manual/07-merchant-products.png)

图 4-1 商家商品维护页面可新增、编辑、上下架和删除商品

### 4.5 维护团购套餐

1. 在商品页面的团购套餐区域填写套餐标题、描述、价格和库存；新增套餐默认启用。
2. 点击保存新增或更新套餐。
3. 可通过列表按钮对套餐执行启用、停用或删除操作。

### 4.6 回复客服消息

1. 进入“客服”页面。
2. 左侧选择用户会话。
3. 查看用户消息和历史记录。
4. 输入回复内容并发送。
5. 可使用商家 AI 辅助生成回复；AI 内容不会自动发送，需先点击“填入回复框”，确认后再点击发送。

### 4.7 维护店铺名称

1. 进入“店铺”页面。
2. 修改商家展示名称。
3. 地址等其他店铺字段为只读；保存后，商家账号昵称和前台店铺名称保持同步。

## 5 平台管理员操作说明

### 5.1 查看平台看板

平台管理员登录后进入“看板”页面，可查看：

| 指标 | 说明 |
|---|---|
| 用户 | 普通用户账号数量 |
| 商家 | 平台商家数量 |
| 今日订单 | 当日订单数量 |
| 今日营收 | 当日已支付订单金额 |
| 完成率 | 配送订单完成比例 |

![平台管理员看板](assets/user-manual/08-admin-dashboard.png)

图 5-1 平台管理员看板展示指标、图表、排行、账号和日志

### 5.2 查看运营分析

平台看板包含订单状态分布、订单类型分布、近 7 日营收趋势、商家排行、配送履约指标和活跃订单列表，用于观察系统当前运行状态。

### 5.3 查看账号列表

管理员可查看普通用户账号和商家账号摘要。普通用户列表展示用户名和昵称；商家列表额外展示店铺 ID。页面不展示密码或密码哈希。

### 5.4 查看系统健康和日志

1. 系统健康状态展示 backend Actuator 汇总状态和待处理订单数量，不等同于所有微服务探针逐项通过。
2. 操作日志展示登录、下单、支付、履约、评价、核销等关键行为。
3. 看板加载失败时可点击“重新加载”。

## 6 常见问题

### 6.1 无法访问前端页面

请确认前端服务已启动，并访问 `http://localhost:5173/`。如果端口被占用，可停止旧进程后重新运行 `npm run dev`。

### 6.2 接口请求失败

先运行 `docker compose ps` 检查默认八个服务，再访问 `http://localhost:8080/actuator/health`。返回 `{"status":"UP"}` 只表示 backend 健康入口可用；完整业务仍依赖 identity、merchant、order、assistant、MySQL 和 RabbitMQ 的健康状态。可使用 `docker compose logs <service>` 查看对应服务日志。

### 6.3 登录后页面没有进入对应角色

请确认当前账号角色正确。普通用户、商家管理员和平台管理员会进入不同导航视图。

### 6.4 AI 客服只有固定回复

如果未配置 `AGNES_API_KEY`，系统会使用确定性兜底回复。默认 remote 模式的模型调用位于 assistant-service；配置环境变量后应重建或滚动重启 assistant-service。只有手工选择 `monolith` 兼容基线时，模型调用才位于 backend。

### 6.5 数据重启后变化

默认 Compose/Kubernetes 通过 MySQL 服务数据库持久化数据，普通的容器重启不会主动恢复种子数据。只有显式清理数据库、删除 Compose 数据卷或重新执行数据清理/种子工具才会改变持久化基线；这些操作不得在共享或生产环境执行。仅在手工选择 `monolith` 本地基线时，兼容实现才可能使用 `LUMALIFE_STATE_FILE` 指定的状态文件。
