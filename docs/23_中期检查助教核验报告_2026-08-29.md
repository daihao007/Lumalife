## 五、第三项：三容器启动与持续集成

### 5.1 三容器

Compose 已定义 `frontend`、`backend`、`mysql` 三个核心运行容器，数据库初始化、迁移和业务状态持久化均有对应脚本和配置。CI 的 `compose-stack` job 会自动：

1. 生成隔离数据库账号；
2. 构建并启动三容器；
3. 检查运行容器数量；
4. 检查后端和前端健康端点；
5. 检查 MySQL 迁移版本和初始化结果；
6. 失败时导出容器状态和日志；
7. 无论成功或失败都清理临时容器和数据卷。

数据库迁移、seed、verify、clean 的复验入口见 [`06_数据库设计.md`](06_数据库设计.md) 和 [`README.md`](../README.md) 的数据库生命周期章节。

### 5.2 CI 自动构建和测试

工作流文件：[`../.github/workflows/ci.yml`](../.github/workflows/ci.yml)。当前质量门禁包含：

| CI job | 自动动作 |
| --- | --- |
| Backend test | Maven 编译、后端测试、上传 Surefire 报告 |
| Frontend build | npm 安装、Vitest、生产构建、上传构建产物 |
| Service skeletons | identity、merchant、order 三个服务独立构建和健康探针验证 |
| Database schema | MySQL 启动、重复迁移、seed、verify、clean 生命周期 |
| Three-container smoke test | Compose 三容器构建、健康检查和数据库初始化校验 |
| API E2E test | HTTP 黑盒业务场景测试 |
| Real UI E2E test | 安装 Chromium、启动后端/前端、运行 Playwright、上传截图/视频/trace/HTML 报告 |
| Kubernetes manifests | Kustomize 清单渲染校验 |
| Quality gate | 汇总测试、构建和清单检查，成功后才进入镜像阶段 |
| Kubernetes rollout smoke test | 在临时 Kind 集群中构建、部署并验证健康探针 |

PR #100 合并前，`Real UI E2E test` 已在 GitHub Actions 通过；该 job 已纳入 `quality-gate`，不是只在本地执行的脚本。

## 六、第四项：微服务划分、接口清单和数据归属

### 6.1 微服务划分方案

当前冻结的目标边界如下：

| 服务 | 业务事实所有者 | 当前实现状态 |
| --- | --- | --- |
| `identity-service` | 用户账号、密码、角色、令牌、地址、商家账号绑定 | 已完成独立业务切片、服务鉴权、持久化文件和后端 Identity Adapter；远程身份切换具备回填闸门 |
| `merchant-service` | 商家资料、分类、商品、团购、库存、收藏、客服和评价读模型 | 已完成独立业务 API、服务鉴权和业务测试 |
| `order-service` | 购物车、订单、支付、券码、评价事实和运营指标投影 | 已完成独立业务 API、服务鉴权和业务测试 |
| 网关/兼容层 | 路由、鉴权入口、兼容 API、请求 ID | 已完成业务边界隔离，不拥有业务表和业务事实 |

目标架构图和服务边界见 [`19_D04C微服务边界接口与数据归属初稿.md`](19_D04C微服务边界接口与数据归属初稿.md)。

| 文档 | 内容 |
| --- | --- |
| [`16_三服务接口数据归属与契约草案.md`](16_三服务接口数据归属与契约草案.md) | 服务所有权、外部 API、内部调用、超时、重试和失败策略 |
| [`docs/contracts/identity-service.openapi.yaml`](contracts/identity-service.openapi.yaml) | identity-service OpenAPI 契约 |

### 6.3 数据表归属方案

数据归属已经按“每张业务表只有一个服务写入”冻结：

| 服务 | 主要事实表/数据集合 | 归属约束 |
| --- | --- | --- |
| identity | `user_account`、`auth_session`、`refresh_token`、`user_address`、`merchant_registration` | 只写身份、会话、地址和商家账号绑定；不拥有商品、订单和库存 |
| merchant | `category`、`merchant`、`product`、`group_deal`、`inventory_reservation`、`merchant_favorite`、`conversation`、`chat_message`、评价投影 | 只写商家经营内容、库存预占、收藏和客服；不写订单主记录和支付事实 |
| order | `cart_item`、`order_main`、`order_item`、状态时间线、支付记录、券码、评价事实、运营指标投影 | 只写购物车、订单、支付、券码和评价事实；商品/地址以快照引用 |

跨服务只传稳定 ID、快照、版本化 API 或事件；禁止跨库 Join、共享可写 Repository 和多个服务共同写入同一事实表。
