# AI 使用、开源与敏感信息说明

> 适用基线：2026-09-03 的 `main`。本文同时区分“开发过程使用 AI”和“系统运行时 AI 能力”，不将二者混为一项。

## 1. 开发过程中的 AI 使用

项目使用 Codex 辅助代码阅读与修改、测试设计、配置检查、文档编辑、图表/PDF 生成与一致性审计。AI 输出不自动构成验收结论，项目成员仍需承担：

- 对业务规则、权限、状态机、数据边界和安全性的人工复核；
- 对代码、测试、配置和正式文档的最终接受；
- 答辩中对本人负责模块的说明，以及个人贡献权重和全员确认的本人填写/签署。

审计过程不会借助 AI 伪造教师确认、成员签名、站会记录、实际工时、测试通过或服务器执行记录。无原始证据的项目保持 `UNVERIFIED` 或 `NOT-RUN`。

## 2. 系统运行时的 AI 能力

当前微服务模式中，`backend` 作为 BFF 将助手请求转发给 `assistant-service`。该服务通过 `AGNES_ENDPOINT`、`AGNES_MODEL` 和 `AGNES_API_KEY` 连接 Agnes 兼容的对话端点。

- `AGNES_API_KEY` 为空或远程提供方不可用时，系统使用确定性 fallback 答复，不将未成功的远程调用表述为大模型生成。
- API Key 只能通过本地 `.env`、CI Secret 或 Kubernetes Secret 注入，不应出现在代码、文档、截图或原始实验产物中。
- 开发过程的 Codex 使用与此运行时功能相互独立。

## 3. 开源使用与来源边界

仓库中的项目特定业务代码和文档围绕课程任务与 LumaLife 需求实现，未声明整仓复制某一开源项目。项目使用的第三方软件通过 Maven、npm 或容器镜像声明引入，主要包括：

- Spring Boot / Spring Security / Spring JDBC / Actuator / springdoc；
- React / Vite / Vitest / Playwright / Recharts / lucide-react；
- MySQL、RabbitMQ、Docker / Compose 和 Kubernetes 工具链；
- 文档导出和质检使用的 ReportLab 与 Poppler。

具体包名和版本以各 `pom.xml`、`frontend/package.json`/lockfile、Dockerfile 和 CI 配置为准。`main@3696741` 已使用 Syft 1.51.0 生成 SPDX 2.3 SBOM，共 287 个条目；249 个具有许可证声明，38 个为 `NOASSERTION`。已声明条目未出现 GPL/AGPL/LGPL/EPL/MPL，但这不等于“所有许可证已全量验证”，对外发布前仍需解析未知项、Maven 传递依赖、容器镜像及素材授权。Grype 0.118.0 对该 SBOM 的扫描发现 11 个开放 npm match（6 High、4 Medium、1 Low），不能宣称当前依赖无漏洞。

## 4. 敏感信息处理

- `.env.example` 只保留变量名、非敏感默认值和明确占位符；实际 `.env` 不得提交。
- MySQL 密码、RabbitMQ 密码、内部服务 Token 和 AI API Key 必须在每个共享/生产环境中分别生成，不复用 Compose 或测试默认值。
- Kubernetes 部署脚本使用 Secret 注入敏感变量；不在静态清单内明文写入真实值。
- 历史实验 YAML 和本地 Compose 存在明确的演示/测试默认值；它们不是生产凭据，也不得用于共享或生产部署。

前序正则扫描见 [`security/secret-scan-2026-09-03.md`](security/secret-scan-2026-09-03.md)。后续专用审计见 [`security/gitleaks-sbom-license-audit-2026-09-03.md`](security/gitleaks-sbom-license-audit-2026-09-03.md)：Gitleaks 8.30.1 对 `3696741` 的 616 个受跟踪文件快照和全部 233 个 Git 提交均为 0 finding。该结论不覆盖本机 `.env`、外部 CI Secret、云平台、未跟踪文件或未知格式凭据，也不是绝对无泄漏证明。

## 5. 提交/答辩前人工检查

1. 确认 `.env`、本机凭据、CI Secret 值和云平台 Token 未进入 Git 、截图、日志或 PDF。
2. 在最终提交变化后复跑 Gitleaks，并确认仍为 0 finding。
3. 处理 SBOM 中 38 个 `NOASSERTION`，修复 Grype 报告的 11 个 npm match，并补充 Maven 传递依赖、容器镜像许可证与漏洞扫描。
4. 如发现真实凭据，先立即撤销/轮换，再清理发布产物和 Git 历史；仅删除当前文件不足以消除风险。
