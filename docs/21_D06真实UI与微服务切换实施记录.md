# D06 真实 UI E2E 与微服务切换实施记录

## 已落地

### 真实 UI E2E（对应 Issue #95）

- 新增独立 `ui-e2e/` Playwright 工程，浏览器运行 Chromium，失败时保留截图、视频和 trace。
- 在关键页面补充稳定 `data-testid`，避免测试依赖易变的 CSS 或文案。
- 当前覆盖真实浏览器操作：登录并进入商家详情、维护收货地址并创建待支付订单、用户和商家在两个浏览器上下文中完成客服往返。
- CI 新增 `Real UI E2E test` job：构建后端、启动后端和前端、安装浏览器、运行场景并上传证据；该 job 纳入质量门禁。

本地运行：

```bash
mvn -B -ntp -f backend/pom.xml package -DskipTests
java -Dlumalife.state-file=/tmp/lumalife-ui-state.json -jar backend/target/lumalife-backend-0.1.0.jar
npm run dev --prefix frontend
npm test --prefix ui-e2e
```

### 微服务业务切片（对应 Issue #96）

- `identity-service`：真实登录、注册、令牌校验、资料和地址 API，使用服务自有密码/用户/地址存储；服务端口要求 `X-Luma-Service-Token`，用户资料和地址还要求匹配的 `X-User-Id`。
- `merchant-service`：真实商家查询、详情、商品查询和商品写入 API；商品写入要求服务令牌和匹配的 `X-Merchant-Id`。
- `order-service`：真实订单创建、按用户查询、待支付订单取消 API；订单创建要求服务令牌，并校验请求体用户 ID 与 `X-User-Id` 一致。
- 后端新增 Identity HTTP Adapter；通过 `LUMALIFE_IDENTITY_REMOTE_ENABLED=true` 选择远程身份服务，但还必须显式设置 `LUMALIFE_IDENTITY_BACKFILL_COMPLETED=true`，否则请求被 `IDENTITY_BACKFILL_REQUIRED` 阻断。
- identity-service 将用户、地址和令牌写入 `LUMALIFE_IDENTITY_STATE_FILE` 指定的持久化文件；商家注册同时分配 `merchantId`，后端首次访问时建立对应的商家能力镜像。
- `GET /internal/migration/status` 只报告真实已接入的 identity 路由；merchant/order 在适配器接入前固定报告 `not-wired`，不再把环境变量误报为远程流量。
- 三个服务都新增鉴权、越权、错误码、商家注册和持久化测试，服务聚合构建通过。

## 仍需完成

- merchant/order 仍没有接入后端 Port Adapter 和真实流量切换；当前只作为受服务令牌保护的独立业务切片，网关仍走单体。
- identity 已具备文件持久化和显式回填闸门，但仍需执行真实历史数据回填/双读校验；三个服务下一步需迁移到各自数据库 schema，并完成幂等、超时/重试、灰度指标和压测。
- 远程身份切换需要在部署环境配置 service URL、`LUMALIFE_INTERNAL_SERVICE_TOKEN`、回填完成标记、网络策略和密钥管理；本地 Docker daemon 不可用时只能完成构建级验证。
