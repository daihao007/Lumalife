# D06 真实 UI E2E 与微服务切换实施记录

## 已落地

### 真实 UI E2E（对应 Issue #95）

- 新增独立 `ui-e2e/` Playwright 工程，浏览器运行 Chromium，失败时保留截图、视频和 trace。
- 在关键页面补充稳定 `data-testid`，避免测试依赖易变的 CSS 或文案。
- 当前覆盖真实浏览器操作：登录并进入商家详情、维护收货地址并创建待支付订单、用户和商家在两个浏览器上下文中完成客服往返。
- CI 新增 `Real UI E2E test` job：构建后端、启动后端和前端、安装浏览器、运行场景并上传证据；该 job 纳入质量门禁。

本地运行：

```bash
mvn -B -ntp -f backend/pom.xml package -DskipTests
java -Dlumalife.state-file=/tmp/lumalife-ui-state.json -jar backend/target/lumalife-backend-0.1.0.jar
npm run dev --prefix frontend
npm test --prefix ui-e2e
```

### 微服务业务切片（对应 Issue #96）

- `identity-service`：真实登录、注册、令牌校验、资料和地址 API，使用服务自有密码/用户/地址存储。
- `merchant-service`：真实商家查询、详情、商品查询和商品写入 API，商品数据只在商家服务内维护。
- `order-service`：真实订单创建、按用户查询、待支付订单取消 API，用户和商家只作为 ID 引用。
- 后端新增 Identity HTTP Adapter；通过 `LUMALIFE_IDENTITY_REMOTE_ENABLED=true` 将身份能力切到远程服务，默认值为 `false`。
- `GET /internal/migration/status` 输出每个域当前走 `monolith` 还是 `remote-service`；关闭对应开关即可回滚。
- 三个服务都新增业务测试，服务聚合构建通过。

## 仍需完成

- merchant/order 还没有接入后端 Port Adapter 和真实流量开关；目前是独立可调用业务切片，网关仍走单体。
- 三个服务当前使用进程内存储，下一步需迁移到各自数据库 schema，并完成历史数据校验、幂等、超时/重试、灰度指标和压测。
- 远程身份切换需要在部署环境配置 service URL、网络策略和密钥管理；本地 Docker daemon 不可用时只能完成构建级验证。
